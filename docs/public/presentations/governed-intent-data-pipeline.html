DS 522 — Data Acquisition and Analytics

Governed Intent-Driven Data Engineering

An architectural framework for AI-assisted data pipelines across the analytics lifecycle

Clark Jason Ngo — MS in Data Science, City University of Seattle
Problem

Natural language is not the same as authority

LLMs can translate a business request directly into pipeline actions — but a fluent response isn't proof the query is correct, the dataset is authorized, or the output is safe to share.

  • Governance gap — prompt-driven workflows skip the controls enterprise data platforms rely on
  • Silent failure modes — non-deterministic transformations, data leakage, unlogged pipeline actions
  • Research question — how can AI-assisted systems translate prompts into data workflows while preserving quality, security, privacy, and accountability?
Approach

Three levels of AI involvement

Advisory
Explains a pipeline or suggests transformations without executing anything.
Assisted
Creates structured plans, code, or queries that a person reviews before execution.
Agentic
Selects tools, retrieves information, executes actions, and observes results directly.

GIDP targets the assisted tier by design — plans are always generated before anything executes.

Core principle

Plan before execute

A request like "Create a weekly customer-retention report using approved subscription and support-ticket data, suppress personal identifiers, and summarize results by region" is never run as raw natural language.

User prompt
→

→
Policy validation
→
Governed execution
→
Audit & lineage

The plan is inspected against role permissions, data classification, tool restrictions, and output requirements — before any database session opens.

Guardrails

Defense in depth, five layers

1  Identity & role-based access controlwho is asking
2  Prompt-injection detectionwhat they're actually asking
3  Catalog authorization & classificationwhat they're allowed to touch
4  Tool allowlists & execution quotaswhat actions are permitted
5  Output & monitoring controlswhat leaves the system

Every layer returns PASS FAIL or ESCALATE — a hard failure denies the request even if every other layer passes.

Implementation

GIDP-Core: a TypeScript control plane

compiler
Composes a structured plan and generates restricted DuckDB SQL
policy
Evaluates identity, injection, catalog classification, tool controls, quotas, HITL elevation
engine
Provides DuckDB and in-memory sandboxes, seed data, quality validation
lineage
Generates hashes and appends tamper-evident audit events
policies
Stores policy-as-code definitions in YAML/JSON
web
Browser-based interactive control-plane laboratory

Assessment

Benefits and limitations

Benefits
Reduces manual effort on repetitive/technical work; makes analytics accessible to domain experts without query syntax; standardizes practice via approved templates and shared policy enforcement.
Limitations
No production LLM planner — deterministic compiler only; mock datasets and in-memory sandbox, not a live database; not a security certification or performance benchmark.

A generated plan can be plausible but incorrect — syntactic validity is not evidence of analytical correctness.

Conclusion

Automation isn't the metric

AI-enabled pipelines should be evaluated not by how much work they automate, but by whether they execute authorized actions, preserve data quality, protect sensitive information, provide traceability, and keep a human accountable throughout the lifecycle.
